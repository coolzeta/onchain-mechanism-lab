## Pending 不是已执行

钱包里的“已提交”、节点的 pending 状态和区块里的 executed state 是三件不同的事。公开交易池更像一个等待室：它让其他参与者看到你的交易意图，却不承诺最终顺序。

<MEVLab focus="core" />

实验室里用户用 12,000 积分换 TOKEN。先点“提交到交易池”，你会看到预估输出，但池子储备还没有移动；继续观察交易池、构建排序，直到执行区块，状态才真正落地。

<Concept title="排序本身就是状态转换的一部分">
<p>如果两笔交易都依赖同一个池子，先执行哪一笔会改变后一笔看到的储备、报价和余额。区块排序不是界面上的装饰，而是共识状态的一部分。</p>
</Concept>

<MechanismDetails>

```text
wallet signs transaction
  → public/private pending flow
  → builder chooses an order
  → proposer publishes a block
  → every node replays the same state transition
```

公开交易池不等于共识层；私有订单流也不等于没有排序权。设计系统时，要分别声明可见性、取消/替换、审查和最终执行边界。

</MechanismDetails>

## 本章留下的审计问题

当你看到任何“MEV 收益”时，先问三件事：谁看见了什么、谁选择了顺序、哪一笔执行真正移动了资产。把这三个边界分开，才能继续分析夹子交易和回跑套利。
